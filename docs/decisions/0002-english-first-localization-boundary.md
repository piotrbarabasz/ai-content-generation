# ADR 0002: English-First Source Production and Localization Boundary

## Status

Accepted

## Context

M006 delivered production/evaluation integrations for Chatterbox Multilingual V3, Piper and XTTS-v2 and preserved provider-neutral narration, chunking, cache and artifact contracts. Manual runtime investigation, including models kept under `experiments/tts_local`, did not justify delaying the core product until an ideal local Polish voice is found.

The product needs one high-quality source production path and a clear handoff to distribution platforms. Content generation, narration, export, localization and publishing are related stages, but they do not describe the same configuration concern.

## Decision

English is the primary source language for production content and narration.

`WorkflowConfig.language` describes the language generated by content modules and synthesized by the source narration path. It must not be repurposed as a list of localization targets or changed during publishing handoff.

Localization configuration belongs at the export and publishing boundary. It records requested target languages, the preferred localization method, manual acceptance state and any custom-audio fallback references without changing the source workflow language.

The intended sequence is:

```text
content generation (English source)
    -> English high-quality narration
    -> YouTube-ready video, audio, captions and metadata export
    -> publishing handoff
    -> preferred platform auto-dubbing
    -> optional custom localized audio fallback
```

Platform automatic dubbing is the preferred first localization path, initially for Polish, but it remains a platform capability rather than a content-generation feature. The application must not claim or invent an unsupported automatic-dubbing API. Handoff metadata and human review may represent the desired localization outcome until an authoritative platform integration supports more.

Publishing remains separate from generation. Platform-specific behavior must be isolated behind export and publishing contracts and selected through configuration and the existing provider registry. `CoreWorkflowEngine` and `VoiceoverModule` must not contain branches such as `if provider == "chatterbox"` or `if platform == "youtube"`.

## Consequences

### Positive

- Core product work can proceed on a single high-quality English production path.
- Source-language artifacts remain internally consistent and reproducible.
- Localization targets can change without invalidating or mislabeling source content.
- Platform capabilities can evolve behind publishing adapters without coupling them to workflow orchestration.
- Custom Polish narration remains available as a fallback and R&D path rather than a release blocker.

### Negative

- Localized output quality and availability initially depend on platform capabilities and human review.
- A complete custom-dubbing workflow remains future work when platform localization is unavailable or unsuitable.
- Publishing configuration and handoff state require explicit contracts in addition to the existing generation configuration.

## Preserved architecture

- TTS provider selection continues through `ProviderConfig`, `TTSSettings`, `TTSFactory` and `ProviderRegistry`.
- `VoiceoverModule`, technical chunking, cache identity, WAV assembly and artifact contracts remain provider-neutral.
- `NarrativeSegment` and `RenderScene` remain separate concepts.
- Experimental MOSS-TTS integrations remain under `experiments/tts_local` and are not registered for production.
- Default tests use deterministic mocks and make no network, model or publishing-platform connection.

## Alternatives considered

### Continue searching for an ideal local Polish TTS before product work

Rejected because the investigation no longer provides enough expected product value to justify blocking export and publishing work.

### Treat Polish as the source language and generate English only for publishing

Rejected because it would make the source content, narration and metadata less coherent and would overload localization concerns onto the generation configuration.

### Put YouTube logic directly in the workflow engine

Rejected because it would couple orchestration to one platform and violate the provider/module boundaries established by ADR 0001.
