# Product roadmap

This is the active backlog for direct application development. Priorities reflect
the inspected code after orchestration cleanup: P0 unblocks a working local
application; P1 enables useful production content; P2 improves operation and use;
P3 is optional output expansion. Items are listed in suggested implementation
order. Implement one coherent change at a time with offline tests.

The engine, local artifact store, domain validation, approval state machine,
Chatterbox/Piper adapters, evaluation XTTS adapter, resumable narration, catalog,
preview API, selection mapper, export and publishing boundaries already exist.
Extend these components. Do not reimplement them as new providers or registries.
Historical task IDs and requirement provenance are in the
[audit](archive/legacy-task-audit.md), not part of this backlog's numbering.

## Connect workflow execution to the API — P0

- **Goal / why:** Starting a run currently only sets `running`. Users need actual
  execution and truthful status, results and errors.
- **Scope:** Add one application composition service for both existing presets,
  injected stores/providers and the current engine. Resolve the short preset's
  missing `scriptGeneration` dependency while preserving brief/transcript inputs.
  Validate before execution and map results, jobs, artifacts and checkpoints into
  the API. Cover both canonical presets with actual module definitions; no stub
  replacements in acceptance tests.
- **Code:** `backend/app/api/routes/workflow_runs.py`, `api/dependencies.py`,
  `workflow/presets.py`, `workflow/registry.py`, module composition boundary.
- **Dependencies:** Existing engine, modules and provider factories.
- **Done when:** An offline HTTP request runs either preset and returns persisted
  artifacts plus completed, failed or waiting-for-approval status as appropriate.

## Persist projects, runs, jobs and decisions across restarts — P0

- **Goal / why:** Module-level API dictionaries lose all project history on restart.
- **Scope:** Introduce a small repository boundary and a local durable implementation
  for project/config/run/job state, artifact indexes and review/localization history.
  Preserve IDs, atomic updates and consistent snapshots; start with single-user
  storage rather than a distributed service.
- **Code:** `backend/app/api/routes/projects.py`, `approvals.py`, `publishing.py`,
  `backend/app/storage/`, domain models and application dependencies.
- **Dependencies:** Execution service above defines persisted lifecycle events.
- **Done when:** Recreating the app recovers a completed and a paused run with
  artifacts and decision history; retry attempts have distinct job records.

## Resume approved workflows and accept artifact revisions — P0

- **Goal / why:** HTTP resume only changes a status; reviewers cannot submit and
  validate a durable revised artifact through a complete application flow.
- **Scope:** Connect review decisions to the engine's seeded results/checkpoints;
  implement controlled revision submission and ownership/version validation.
  Preserve rejected outputs, block unresolved checkpoints and avoid regenerating
  completed steps. Reuse the existing approval state machine.
- **Code:** `backend/app/api/routes/approvals.py`, `workflow_runs.py`,
  `domain/approval.py`, application execution service, storage.
- **Dependencies:** Execution service and durable state.
- **Done when:** HTTP reject/request-changes preserves the original; an approved
  revision resumes only downstream work, including after an application restart.

## Deliver real export bundles and artifact downloads — P0

- **Goal / why:** The export API constructs references without saving its claimed
  files. Users need to retrieve the output already generated by `ExportModule`.
- **Scope:** Connect export requests to stored module output; expose controlled
  artifact/bundle downloads with integrity checks, ownership validation and honest
  missing-optional-artifact reporting. Preserve approval summaries.
- **Code:** `backend/app/api/routes/artifacts.py`, `workflow_runs.py`,
  `modules/export.py`, `modules/export_manifest.py`, `storage/`.
- **Dependencies:** Execution, durable state and review integration.
- **Done when:** API-delivered bytes match stored checksums and required bundle
  files; unknown/traversal identifiers fail without probing arbitrary paths.

## Add a real text-generation provider — P1

- **Goal / why:** Script/research/outline boundaries currently use deterministic
  mock text. Useful generated content needs a configured real adapter.
- **Scope:** Implement one adapter behind `LLMProvider`, strict settings and lazy
  composition, structured output validation, safe errors and usage reporting.
  Keep mocks as defaults and runtime credentials outside serialized configs.
- **Code:** `backend/app/providers/`, `modules/script_generation.py`,
  `modules/research.py`, `modules/outline.py`, `workflow/usage.py`.
- **Dependencies:** Existing protocols; execution integration for user acceptance.
- **Done when:** Offline transport tests cover text, schema validation, timeout,
  throttling and redaction; an explicit manual smoke can generate a real script.

## Ground research in supplied sources — P1

- **Goal / why:** Current research normalizes supplied descriptions and mock text;
  it does not retrieve and verify source material.
- **Scope:** Add validated source ingestion, preserved source identity/provenance,
  fact-to-source references and QA for unsupported claims. Combine the old
  ingestion/research/dossier migration ideas into one narrow vertical slice.
- **Code:** `backend/app/modules/research.py`, `dossier.py`, `qa.py`,
  provider boundary and artifact storage.
- **Dependencies:** Real text-generation adapter and durable artifacts.
- **Done when:** Supplied fixture sources yield attributable research and dossier
  facts; missing/unreadable sources and unsupported claims are reported honestly.

## Manage approved reference audio for TTS — P1

- **Goal / why:** Reference-mode contracts exist, but the default API has no
  approved-artifact resolver or reference intake flow.
- **Scope:** Add controlled audio intake and approval metadata, validate WAV and
  checksum, wire an opaque-ID resolver into previews and workflow composition.
  Reuse the current catalog and selection mapper; reject unapproved references.
- **Code:** `backend/app/api/dependencies.py`, reference artifact API/storage,
  `tts/preview.py`, `tts/selection.py`, `providers/tts_factory.py`.
- **Dependencies:** Durable state, artifact access and review integration.
- **Done when:** The same approved reference ID works for preview and narration;
  changed bytes invalidate identity and no public payload leaks a private path.

## Align speech and produce synchronized captions — P1

- **Goal / why:** Word timings are currently distributed evenly over audio duration;
  mock caption timings do not establish synchronization with spoken words.
- **Scope:** Add a real transcription/alignment adapter, preserve text order and
  provenance, feed measured timing into scene/caption preparation, and retain
  existing SRT validation/export. Combine speech timing and caption synchronization.
- **Code:** `backend/app/providers/interfaces.py`, transcription/caption adapters,
  `modules/voiceover.py`, `modules/captions.py`, `domain/caption_track.py`.
- **Dependencies:** Existing WAV generation and stored audio access.
- **Done when:** Offline fixtures exercise aligned timestamps and failed alignment;
  explicit manual acceptance checks synchronization against real narration.

## Plan and supply visual assets for scenes — P1

- **Goal / why:** Rendering currently receives references without a managed visual
  asset selection path.
- **Scope:** Combine asset planning and selection: scene visual requirements,
  controlled user-supplied image/video intake, assignments, checksums and source/
  license metadata. Add one real asset adapter; generated images can be a later
  adapter under the same boundary rather than a prerequisite for basic rendering.
- **Code:** `backend/app/modules/scene_planning.py`, `providers/interfaces.py`,
  asset adapter/service, `domain/render_scene.py`, `storage/`.
- **Dependencies:** Durable artifacts and existing scene planning.
- **Done when:** Every render scene resolves to an approved usable asset or an
  explicit missing-asset error; local source paths never enter public manifests.

## Render playable video with an optional real renderer — P1

- **Goal / why:** `render.mp4` currently stores a mock URI string, not video bytes.
- **Scope:** Implement one local renderer behind `VideoRendererProvider`, with
  validated media output, audio/caption inputs and configured resolution/FPS.
  Define a justified media-result contract so the module persists bytes or a
  controlled artifact, never a text URI presented as playable MP4.
- **Code:** `backend/app/providers/`, `modules/video_rendering.py`,
  `domain/video_render.py`, storage/export integration.
- **Dependencies:** Canonical short workflow, supplied visual assets; alignment
  for synchronized captioned output, existing TTS for optional narration.
- **Done when:** Fake-process tests cover failures and persistence; an explicit
  local media smoke produces a playable clip whose checksum matches the export.

## Connect publishing handoffs to durable application operations — P1

- **Goal / why:** Publishing adapters exist, but the HTTP handoff state is
  disconnected from durable export/decision storage.
- **Scope:** Register actual export handoffs, persist every localization decision,
  expose an explicit approved publishing action and preserve publication identity
  across retries/restarts. Reuse YouTube transport and fallback metadata; keep
  auto-dubbing availability/acceptance manual.
- **Code:** `backend/app/api/routes/publishing.py`, `modules/publishing.py`,
  `providers/publishing_factory.py`, `providers/youtube_publishing.py`, storage.
- **Dependencies:** Durable state, approved real exports; renderer for video upload.
- **Done when:** Offline HTTP-to-fake-transport tests prove approval gating and
  durable retry/decision history without duplicate uploads or fabricated dubbing.

## Build a minimal project, review and voice-selection UI — P2

- **Goal / why:** The backend has discovery/preview contracts but no user interface.
- **Scope:** Project configuration, compatible provider/model/voice selection,
  preview playback, run status, artifact review and export download. Consume
  existing camelCase API contracts; avoid a second persisted selection model.
- **Code:** A small new frontend and existing `backend/app/api/` endpoints.
- **Dependencies:** Working execution/review/export APIs; reference intake only
  for reference-voice selection.
- **Done when:** A user completes both supported workflows without editing Python
  or filesystem paths; selecting a voice preserves preview/production identity.

## Run long content jobs in the background — P2

- **Goal / why:** Real narration/rendering can outlast an HTTP request and needs
  visible progress, cancellation and safe recovery.
- **Scope:** Add a bounded application job worker with durable lifecycle/progress,
  cancellation and restart recovery. Reuse `WorkflowRun`, `GenerationJob` and TTS
  resume caches. This executes content modules, not coding agents.
- **Code:** Application execution service, `backend/app/workflow/`, job storage,
  `api/routes/workflow_runs.py`, `tts/chunk_synthesis.py`.
- **Dependencies:** Durable lifecycle and connected execution/review services.
- **Done when:** Simulated interruption/cancellation preserves completed artifacts
  and reports truthful status; resume does not duplicate completed work.

## Add an optional thumbnail output — P3

- **Goal / why:** Video publishing needs a reviewable thumbnail; this was a deferred
  product concept, not an implemented module.
- **Scope:** Produce a thumbnail from approved supplied/generated visuals, persist
  it as an artifact and include it in export metadata; keep the stage optional.
- **Code:** New small module, asset boundary, export/handoff mapping.
- **Dependencies:** Visual asset support and real video/export path.
- **Done when:** Disabled thumbnails require no provider; enabled output is
  inspectable and never blocks nonvisual workflows.

## Scope decisions

Audio-only/script-only are supported content-type concepts; first validate them
through the existing nonvisual workflow instead of creating duplicate engines.
Additional editorial presets and generative-image adapters can follow demonstrated
use cases. Multi-user workspaces, billing, advanced analytics, marketplaces,
automatic publishing schedules and a standalone brand/template system are not
recommended implementation work until the local product path above is complete.
Do not reintroduce development task orchestration to deliver any of these features.
